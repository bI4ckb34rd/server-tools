# راهنمای کاربر

> ترجمهٔ فارسی — نسخهٔ مرجع انگلیسی است: [GUIDE.md](GUIDE.md) · ServerTools 2.4.6

## ۱. این ابزار چیست

ServerTools تشخیص می‌دهد سرور چه کاری می‌کند — یعنی **نقش‌های** آن — و تنظیماتی را اعمال می‌کند که با همان
نقش‌ها جور است. نقش‌ها با هم ترکیب می‌شوند؛ اگر نقش خاصی پیدا نشود نقش `general` اعمال می‌شود که
بهینه‌سازی کامل عمومی است، نه نسخهٔ کم‌شده.

| نقش | نرم‌افزارهای معمول |
| --- | --- |
| `proxy` | Xray/Reality، sing-box، Hysteria2، TUIC، نودهای Marzban/Pasarguard/Remnawave، x-ui، Hiddify |
| `panel` | داشبورد Marzban، Marzneshin، Pasarguard، Remnawave |
| `vpn` | WireGuard، AmneziaWG، OpenVPN، OpenConnect، IPsec، SoftEther، Tailscale |
| `tunnel` | GRE، IPIP، SIT، ip6tnl، VXLAN، Geneve، FOU/GUE |
| `relay` | فوروارد پورت با DNAT در iptables یا nftables به سرور دیگر |
| `utunnel` | Backhaul، Rathole، gost، frp، Chisel، WaterWall، udp2raw، kcptun |
| `web` | nginx، Caddy، Apache، HAProxy، Traefik، Envoy — سایت، وب‌هوک ربات، رلهٔ L4 |
| `db` | MySQL، MariaDB، PostgreSQL، Redis، Valkey، MongoDB، ClickHouse |
| `general` | هر چیز دیگر |

سرورهایی که Docker دارند یک مرحلهٔ Docker هم می‌گیرند. سرورهای تانل و رله راهنمای جدا دارند:
[TUNNELS.fa.md](TUNNELS.fa.md).

ابزار اجرا می‌شود، تنظیم می‌کند و خارج می‌شود. چیزهایی که باید بعد از ریبوت بمانند با سرویس‌های کوچک
یک‌باره‌ای اعمال می‌شوند که آن‌ها هم بعد از کار خارج می‌شوند.

## ۲. پیش‌نیازها و نصب

- دسترسی root (`sudo -i`)؛ Ubuntu 20.04+ یا Debian 11+ (تست‌شده در CI) — توزیع‌های دیگر با apt، dnf/yum یا
  pacman معمولاً کار می‌کنند؛
- اینترنت برای دانلود و نصب پیش‌نیازها.

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Sir-Adnan/server-tools/main/dist/server-tools.sh) --install
```

بعد `st` منو را باز می‌کند و `st --update` به‌روزرسانی می‌کند (با بررسی `SHA256SUMS` نسخه). بدون `curl`:
`bash <(wget -qO- URL)`.

پیش‌نیازها (`ethtool`، `nftables`، `iproute2`، `iptables`، `procps`، `kmod`، `curl`؛ `dig` برای تست DNS؛ `jq`
برای مرحلهٔ Docker) اگر نباشند نصب می‌شوند — بدون بسته‌های اضافه — و روی صفحه و در `st --report` اعلام می‌شوند.
خاموش کردن: `--no-install` یا `st --set install_deps=never`.

## ۳. داشبورد

بالای منو نشان می‌دهد: میزبان، سیستم‌عامل و کرنل؛ CPU و RAM؛ IP عمومی، الگوریتم ازدحام، qdisc و وضعیت
**IPv6**؛ **نقش‌ها** و موتورهای تشخیص‌داده‌شده؛ و **وضعیت**: بهینه‌شده (نقش‌ها، تیر)، هنوز بهینه نشده، یا — اگر
ریبوت یا ابزار دیگری چیزی را برگردانده باشد — چند تنظیم کرنل دیگر اعمال نیست و راه رفعش.

سروری که با ServerTools 2.4.4 یا قدیمی‌تر بهینه شده، یک بار پیشنهاد ارتقا می‌بیند تا چیزهایی که آن نسخه‌ها
اشتباه گذاشته بودند اصلاح شود — ثبت‌شده و قابل برگشت.

## ۴. بهینه‌سازی سریع (گزینهٔ ۱) — مسیر پیشنهادی

1. پیش‌نیازهای ناموجود نصب می‌شوند.
2. پلن نمایش داده می‌شود: نقش‌ها و موتورها، تیر ظرفیت، اندازهٔ conntrack و RAM بدترین حالتش، جدول
   **تصمیم‌ها و دلیل‌ها**، کارهای اختیاری‌ای که CPU را کم می‌کنند و هنوز فعال نیستند، و بررسی تانل‌ها.
3. سرویس DNS را انتخاب کنید (`t` همه را تست می‌کند؛ `0` یعنی DNS فعلی دست نخورد).
4. تأیید کنید. مراحل یکی‌یکی اجرا می‌شوند:

```text
[1/9] Swap ... SKIPPED
[2/9] Kernel network tuning (sysctl), tier M ... OK
[3/9] Queueing discipline on eth0 (fq_codel) ... OK
[4/9] CPU & NIC data path (channels, offloads, IRQs, RPS/XPS) ... OK
[5/9] MSS clamping for forwarded TCP ... OK
[6/9] File-descriptor limits (nofile) ... OK
[7/9] Journald cap & NTP ... OK
[8/9] Docker engine (log rotation, live-restore, nofile) ... OK
[9/9] DNS (1.1.1.1 / 1.0.0.1) ... OK
```

OK = اعمال و بررسی شد · SKIPPED = لازم نبود (swap از قبل هست؛ داخل کانتینر LXC/OpenVZ، swap و ساعت مال
میزبان‌اند) · WARN = اعمال شد با یک نکته · FAILED = اعمال نشد. MSS برای `vpn`، `tunnel` و `relay` اجرا
می‌شود و Docker فقط وقتی Docker در حال اجراست.

**کارهایی که Quick انجام نمی‌دهد** — چون مسیر فایروال یا سیستم را طوری عوض می‌کنند که به سرور بستگی دارد، با
انتخاب خودتان است: UFW، fail2ban، سخت‌سازی SSH (منوی ۶)؛ NOTRACK، مسیر سریع nftables، خاموشی IPv6، XanMod،
mirror مخزن (منوی ۷ و کلید `i`). Quick تعداد کاربر را هم نمی‌پرسد — بخش Custom را ببینید.

**مرحلهٔ Docker.** فایل `/etc/docker/daemon.json` با `jq` **ادغام** می‌شود و کلیدهای خودتان همیشه حفظ
می‌شوند: لاگ json-file با `max-size=10m` و `max-file=3` (`docker_log_size`)، روشن شدن `live-restore` (غیر از
Swarm) و `nofile=1048576` برای کانتینرها. dockerd فقط reload می‌شود و هیچ کانتینری متوقف نمی‌شود. محدودیت لاگ و
nofile به کانتینرهایی می‌رسد که بعد از ری‌استارت Docker ساخته شوند — ری‌استارت در پایان پیشنهاد می‌شود (با
live-restore کانتینرها روشن می‌مانند)؛ برای ساخت دوباره: `docker compose up -d --force-recreate`.

**ری‌استارت سرویس‌ها.** اگر سقف فایل واقعاً تغییر کرده باشد، ری‌استارت سرویس‌های پروکسی و تانل پیشنهاد
می‌شود تا سقف جدید را بگیرند.

## ۵. بهینه‌سازی سفارشی (گزینهٔ ۲)

- **نقش‌ها**: یکی یا چندتا (مثلاً `1,4`)؛ Enter یعنی همان تشخیص خودکار؛ می‌شود انتخاب را ذخیره کرد.
- **تیر ظرفیت** (S/M/L/XL): از روی RAM انتخاب می‌شود؛ تیر دستی برای همین اجرا اعمال می‌شود و ذخیره‌اش جدا
  پرسیده می‌شود.
- **تعداد کاربر همزمان**: conntrack را از روی تعداد واقعی کاربر تنظیم می‌کند، با هشدار صادقانه اگر RAM کافی
  نباشد (قاعدهٔ سرانگشتی: حدود ۸ گیگ RAM برای هر ۱۰هزار کاربر پروکسی).
- سپس تک‌تک مراحل: CPU/NIC، MSS، limits، journald/NTP، Docker، swap، DNS.

چرا سرور ۴ گیگ تیر M می‌گیرد و چرا L آن را سریع‌تر نمی‌کند: [پرسش‌های متداول](FAQ.fa.md).

## ۶. اجرای بدون سؤال

```bash
st --auto                                   # تشخیص و اعمال
st --auto --role proxy --dns cloudflare     # نقش دستی + DNS
st --auto --role relay,tunnel --no-swap     # رلهٔ GRE/DNAT
st --auto --users 10000                     # conntrack برای ۱۰هزار کاربر
```

بدون `--dns` به DNS دست نمی‌زند. `--no-swap`، `--no-limits`، `--no-extras`، `--no-perf`، `--no-mss` و
`--no-docker` مراحل را حذف می‌کنند. نام پروفایل‌های 2.4.4 و قدیمی‌تر (`--profile vpn-node|wireguard|panel|relay|full`)
هنوز کار می‌کنند.

## ۷. اجرای آزمایشی (Dry run)

```bash
st --dry-run
st --dry-run --role relay,tunnel --users 10000
```

تصمیم‌ها با دلیل، فایل کامل sysctl، مقایسهٔ کلیدبه‌کلید با کرنل، کلیدهایی که فایل دیگری هنگام بوت رویشان
می‌نویسد، همهٔ تغییرات `/sys`، وقفه‌ها و ethtool، و ادغام Docker — و در آخر
`N of M keys would change. Nothing was applied.`

## ۸. بعد از ریبوت

همهٔ تنظیمات طوری ذخیره می‌شوند که بعد از ریبوت بمانند (جزئیات: [SYSCTL.md](SYSCTL.md#surviving-reboots)).
برای بررسی:

```bash
st --verify            # یا گزینهٔ ۴ — Doctor
```

داشبورد هم اگر تنظیمی دیگر اعمال نباشد هشدار می‌دهد. اگر چیزی عوض شده (ابزار دیگری بازنویسی کرده)،
Quick Optimize را دوباره بزنید: تکرارش بی‌خطر است و علت را هر جا بتواند رفع می‌کند — مثلاً کلیدهایی از
`/etc/sysctl.conf` که روی تنظیمات ما می‌نوشتند، کامنت می‌شوند (ثبت‌شده).

## ۹. عیب‌یابی مسیر داده (کلید d)

```bash
st --diagnose
```

اندازه‌گیری حدوداً ۳ ثانیه‌ای: softirq، system و steal و بسته/drop هر هسته، صف‌ها و channelهای کارت شبکه،
ماسک‌های RPS/XPS، جای وقفه‌های دریافت و irqbalance، GRO، drop صف، مصرف و drop جدول conntrack، محدودیت لاگ
Docker و بررسی MTU تانل‌ها — با نتیجه‌گیری و دستورهای دقیق برای مقایسهٔ A/B. هیچ چیزی تغییر نمی‌کند. نحوهٔ
خواندنش: [TUNNELS.fa.md](TUNNELS.fa.md).

## ۱۰. Doctor، وضعیت و گزارش

- `st --verify` (گزینهٔ ۴): هر بخش OK، تنظیم‌نشده، یا DRIFT همراه راه رفع؛ به‌علاوهٔ شمارنده‌های retransmit و
  drop از آخرین اجرا. برای مانیتورینگ: `--verify --json`.
- `st --status` (گزینهٔ ۳): سیستم، CPU/RAM/دیسک، شبکه، DNS فعال، وضعیت تنظیمات، limits، امنیت، نقش‌ها.
- `st --report`: گزارش متنی کامل برای پشتیبانی، چاپ و ذخیره در `/var/lib/server-tools/`.

## ۱۱. روشن/خاموش کردن IPv6 (کلید i)

```bash
st --ipv6 off          # یا: on، status
```

کل IPv6 را خاموش (IPv4 کار می‌کند) یا روشن می‌کند، بدون ریبوت — و بعد از ریبوت هم خاموش می‌ماند: یک سرویس
یک‌باره بعد از بالا آمدن شبکه، IPv6 را روی هر کارت دوباره خاموش می‌کند. روی سروری که فقط IPv6 دارد انجام
نمی‌شود؛ اگر SSH شما روی IPv6 باشد منو می‌پرسد و خط فرمان رد می‌کند. منو کارت‌هایی که IPv6 رویشان برگشته را
نشان می‌دهد و درستشان می‌کند.

## ۱۲. تست سرعت (منوی ۷ ← ۹)

```bash
st --speedtest
```

از کلاینت رسمی Ookla استفاده می‌کند — یک بار دانلود می‌شود (حدود ۱ مگابایت) و در `/var/lib/server-tools/bin`
**می‌ماند** — با انتخاب سرور خودکار، نزدیک، با شناسه، یا «۳ سرور نزدیک پشت سر هم»؛ اگر نشد از تست HTTP موازی
استفاده می‌کند. هر نتیجه ذخیره می‌شود؛ پنج نتیجهٔ آخر بعد از هر تست نشان داده می‌شود و `h` بیشتر نشان می‌دهد.
قبل و بعد از بهینه‌سازی، در ساعت مشابه، تست بگیرید تا مقایسه کنید. گزینهٔ ۹ همان صفحه کلاینت ذخیره‌شده را
پاک می‌کند.

## ۱۳. امنیت (منوی ۶، همه اختیاری)

- **UFW** — پورت SSH قبل از هر قانون deny باز می‌شود؛ روی سرورهای فورواردر `DEFAULT_FORWARD_POLICY=ACCEPT`،
  GRE از طرف مقابل تانل و پورت وایرگارد را باز می‌کند تا فعال کردن فایروال تانل را قطع نکند.
- **fail2ban** — مسدودسازی حملهٔ SSH؛ یک سرویس دائمی (حدود ۲۰ مگابایت RAM).
- **سخت‌سازی SSH** — ورود فقط با کلید، فقط وقتی کلید وجود دارد؛ قبل از ری‌استارت با `sshd -t` بررسی می‌شود.
- **Anti-abuse** — پورت‌های SMTP/کرم و رنج‌های خصوصی را می‌بندد، ولی همهٔ زیرشبکه‌های متصل (LAN دیتاسنتر،
  تانل‌ها، Docker، وایرگارد) باز می‌مانند.
- **محدود کردن API نود** — پورت‌های 62050/62051 فقط برای IP پنل.
- **بررسی Docker + UFW** — پورت‌هایی که Docker از کنار فایروال باز می‌کند.

## ۱۴. ابزارهای شبکه و VPN (منوی ۷)

| کلید | ابزار |
| --- | --- |
| d · t | عیب‌یابی مسیر داده · بررسی تانل (MTU، encapsulation، MSS) |
| 5 | MSS clamping |
| n | NOTRACK برای پورت‌های پروکسی (فقط ترافیکِ مقصد خود سرور) |
| f | مسیر سریع nftables flowtable برای رله و گیت‌وی VPN |
| i | روشن/خاموش IPv6 |
| 1 · 2 · 3 · 4 | پینگ · تأخیر DNS · TCP/conntrack · پورت‌های باز |
| 9 · b · w | تست سرعت · بنچمارک سریع · نمای زنده |
| 8 · m · 7 | کرنل XanMod/BBRv3 · mirror مخزن · گزارش پشتیبانی |

## ۱۵. نود و Docker (منوی ۸)

- **پشتیبان‌گیری از تنظیمات نود** (`/opt/marzban-node`، `/opt/pg-node`، `/etc/wireguard` و…) — فایل شامل
  کلیدهاست؛ خصوصی نگهش دارید.
- **نصب نود** با نصب‌کنندهٔ رسمی — دستور کامل اول نشان داده می‌شود.
- **موتور Docker** — بررسی (live-restore، محدودیت لاگ، بزرگ‌ترین لاگ‌ها، تعداد docker-proxy،
  `docker system df`)، همان ادغام مرحلهٔ Quick، و خالی کردن لاگ‌های بالای ۱۰۰ مگابایت (قبلش می‌پرسد؛ متن لاگ
  برنمی‌گردد).

## ۱۶. برگرداندن تغییرات (منوی ۵)

```bash
st --rollback            # برگرداندن آخرین اجرا؛ دوباره = یک اجرا عقب‌تر
st --rollback-original   # همه‌چیز به قبل از اولین اجرای ServerTools
```

فایل‌های تغییرکرده برمی‌گردند، فایل‌های ساخته‌شده حذف می‌شوند، سرویس‌ها غیرفعال (و قوانینشان پاک) می‌شوند،
مقادیر زنده (RPS/XPS، وقفه‌ها، THP، governor، channel و offloadهای کارت شبکه) و qdisc برمی‌گردند و sysctl
دوباره بارگذاری می‌شود. بسته‌های نصب‌شده حذف نمی‌شوند. جزئیات: [ROLLBACK.md](ROLLBACK.md).

## ۱۷. تنظیمات (منوی ۹)

```bash
st --settings                  # همهٔ تنظیمات با مقدار و توضیح
st --set rps_mode=off          # خاموش کردن RPS
st --set roles=relay,tunnel    # تعیین دستی نقش‌ها
st --set capacity_tier=L       # تیر اجباری
st --set irq_affinity=off      # دست نزدن به وقفه‌های کارت شبکه
st --set docker_tuning=off     # دست نزدن به daemon.json
```

مقادیر بررسی می‌شوند و در اجرای بعدی اعمال می‌شوند.

## ۱۸. رفع مشکلات

| مشکل | راه‌حل |
| --- | --- |
| «must be run as root» | `sudo -i` و دوباره اجرا |
| تنظیمات بعد از ریبوت پریده | `st --verify`، بعد دوباره Quick Optimize — بخش ۸ |
| DNS به DNS دیتاسنتر برگشته | Quick را با DNS خودتان دوباره بزنید؛ حالا networkd، NetworkManager و dhclient پین می‌شوند |
| مصرف CPU بعد از بهینه‌سازی بالا رفت | `st --diagnose`؛ [TUNNELS.fa.md](TUNNELS.fa.md)؛ مقایسه با `st --set rps_mode=off && st --auto` |
| تانل بعد از فعال کردن UFW قطع شد | راه‌اندازی UFW را از منوی ۶ دوباره بزنید — فوروارد و GRE را باز می‌کند |
| دیسک سرور Docker پر شد | منوی ۸ ← موتور Docker: بررسی، محدودیت لاگ، خالی کردن لاگ‌های بزرگ |
| `nf_conntrack: table full` در `dmesg` | Quick را دوباره بزنید؛ با کاربر زیاد `--users N` بدهید |
| نصب یک پیش‌نیاز شکست خورد | `/var/log/server-tools.log`؛ آن قابلیت از روش جایگزین استفاده می‌کند |
| رنگ‌ها به‌هم ریخته | `st --no-color` یا `NO_COLOR=1` |
